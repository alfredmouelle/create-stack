## Native Remix

This application uses Remix 3 and `remix/component`, with native server rendering and browser entries. Projects with email use React only for transactional email rendering. Components in `src/client` use Remix handles, events, and client entries. Keep secrets and database code in `src/server`. Only explicit public files and approved browser packages are served by the asset server.

The home, theme, auth screens, and email identity match the other Create Stack frameworks. When selected, Better Auth uses native POST forms, same-origin checks, Better Auth cookies, and request-scoped sessions. Google sign-in requires the optional Google credentials. Projects with tRPC include `/api-demo` for the vanilla browser client. Hosted providers require their own credentials.

## Production

Run application scripts from `apps/web` in a monorepo, or from the project root in a standalone project. Use Node 24.19.0 or newer. Install production dependencies and deploy `src`, `scripts`, `public`, `package.json`, `tsconfig.json`, and installed dependencies together. Set `NODE_ENV=production`, `PORT`, `HOST`, and the selected provider variables, then run `__RUN__ start`. Bind `HOST=0.0.0.0` behind a trusted HTTPS reverse proxy. Set the auth origin to the public HTTPS URL. When terminating HTTPS at a reverse proxy, set `TRUST_PROXY=1` and configure that proxy to overwrite forwarded host/protocol headers. Direct Node deployments keep proxy trust disabled by default.

Remix compiles browser assets on demand. Tailwind compiles once per production process. There is no application build directory or build script, and monorepo cache outputs are empty. Restart after changing deployed source. Run `__RUN__ typecheck`, `__RUN__ check`, and `__RUN__ test` before deployment. SQL projects use a separate PostgreSQL database for tests.

Native component additions live in `src/client/ui`, with convenient exports in `src/components`. Compose interactive date pickers and tables inside a `clientEntry`. Create typed table components with `createDataTable<Row>()` and `createInfiniteDataTable<Row>()` and supply stable `getRowId` values. Callable dialogs mount once in the document and expose `Confirm.call`, `Alert.call`, `Prompt.call`, `Choice.call`, `ConfirmPassphrase.call`, and `ConfirmOtp.call`. Native dialogs trap focus, restore focus, support Escape, and queue concurrent calls. OTP verification calls the supplied asynchronous verifier.

Clerk uses its browser SDK for provider-owned sign-in UI and its backend SDK for request-scoped identity. Convex uses its vanilla client for subscriptions and mutations. When combining them, configure a Clerk JWT template named `convex` with audience `convex`. In the Convex deployment environment, set `CLERK_ISSUER_URL` to your Clerk Frontend API URL using the Convex CLI command `convex env set CLERK_ISSUER_URL <issuer-url>`, then deploy the generated `convex/auth.config.ts`. Configure `REMIX_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, and `CLERK_AUTHORIZED_PARTIES` in the application environment. `CLERK_JWT_KEY` optionally enables offline JWT verification with the Clerk public PEM key. Sentry uses Node preload instrumentation plus explicit stream, application, browser, and native runtime error hooks. Source maps from runtime compilation require a deployment-specific upload workflow. No framework SDK or automatic route naming is claimed.

Transactional email files use React `createElement` (and React JSX-runtime calls) explicitly. Keep their rendering isolated from native Remix page JSX. Native Oxlint overrides disable React display-name and React checked/onChange checks only for native UI: Remix returns render closures and registers input handlers through `mix`/`on`. Type-aware checks and all strict TypeScript profile options remain enabled.
